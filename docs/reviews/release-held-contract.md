# Held-to-normal release, review draft

Status: NOT EXECUTABLE ON A REAL HOST. Host.preflight retains an unconditional refusal. Local unit tests do not qualify the host or a restored production dataset.

## Exact starting contract

Release is same-image only. Before release, the durable format3 history tip and recovery fence must match both the live SHA and immutable digest, with ui-open-automation-held and automation_held=true. A direct running-image and HOLD observation now precedes preflight and every journal mutation; mismatch refuses before an intent. Pause remains present, HOLD remains 1, no pending/failed/opening intent. The recovered host currently does not meet this contract: its historical delivered tip differs from its live restored image. Release must refuse this mismatch, never rewrite history or silently adopt the current image.

A separate reviewed recovery/adoption must establish source ancestry, actual image digest, migration ledger, preservation, gates and observed runtime, and append an audit for the restored target while retaining the original incident, pause and HOLD. Existing adoption entry points do not cover an already resolved format3 held state with a different live image. A new reconcile-restored-held.py implementation is now included for incremental review, but has not been executed on E5. A fabricated pending/failed pair is not acceptable.

## Isolation contract required before enabling preflight

An isolated rehearsal must use a coherent stopped copy of all three stores, a distinct Docker network with no external egress, no published app port, no host-network mode, no Docker socket, no production bind mounts, no production credentials and no production endpoints. Only fixture credentials and fixture upstreams are allowed. The copy's original encrypted credentials must not become usable by importing the production decryption key. Mount/image/network inspection plus negative egress probes and upstream request counters must prove these claims before the first normal boot. Declared booleans or a receipt with complete=true do not prove isolation.

The rehearsal must execute the exact release controller and image, record hashes of controller bytes, all input copies, env before/after, policies and runtime profile, and show the expected synthetic effects and refusal cases. It must verify that source production stores are unchanged. This executor and independent evidence verifier remain UNIMPLEMENTED. Host.preflight therefore remains closed. It is not sufficient to supply a hand-authored isolated_qualification JSON.

## Backlog evidence

release-backlog.mjs is a read-only producer intended for execution inside the held app, using its live SQL server. It enumerates every database/branch and binds working roots before and after, hashes all rows in relevant workflow runtime/configuration/cursor tables, and exports counts and hashes only, plus excluded table names. inventory_complete describes only the listed SQL inventory. external_coverage remains unverified. Missing runtime table, moving roots or query errors refuse. It does not claim that upstream events are absent, nor that the current capture alone authorizes replay. Tests use a fake SQL connection; actual Dolt execution is still required.

The adapter now recaptures with the hash-bound installed producer after both gates are proved 503 and before docker stop. It compares exact branch/table entries and their inventory digest, ignoring only capture time; any delta or reached row ceiling refuses before stop. A durable hash/time of this recapture is retained in the release intent. No exclusion of audit/session mutations is permitted: moving roots mean refuse and recapture, not relaxed coherence. Preventing all new non-front webhook ingress remains a separate required host proof. Local row content must be reviewed privately for recipient/provider/action scope, retained locks, inbox items and external event catch-up. Hashes alone cannot prove that scope. Both internal inventory and external upstream reconciliation are required before effects.

## Commit and failure contract

Install and verify the format4-aware boot guard and all readers/controllers before any format4 writer or HOLD removal. Disable/mask boot supervision and exclude competing mutators during bootstrap. Acquire journal and actual updater locks. Keep a durable release intent, including subprocess identity and inherited lock, before each action. Close both public access gates and prove 503. Stop the held app and capture preservation evidence. Prepare and atomically install the reviewed normal policy, preserving unrelated environment bytes. Leave HOLD1 in the environment through preservation and all precommit checks.

The durable normal-start-committed marker now precedes HOLD removal itself. start_normal refuses without that marker, installs the environment and persists its hash proof, then starts the exact image. The marker also precedes the first non-HOLD boot. This boot can resume workflows and cause external effects even while the public front returns 503. Health is not the effects commit. No automatic retry, restore, old-image boot or rollback after this marker. An interruption may only rearm access once the exact queue and child are proven absent. Unknown identity remains report-only. A committed release can remove only its own exact pause bytes; separate finalization does not restart or replay.

## Paths and future CI

Every effective path must be explicit and consistent: env, ordered queue, state, pause, updater lock, boot script, qualification policy/postcheck, data, backups and both access gates. Active restored trees must not fall through to /opt/lyam defaults. Future qualification must use the committed normal policy requireAutomationHold=false. The prior policy must be retained and hash-bound. The operational policy path is explicitly bound through LYAM_QUALIFICATION_POLICY; update.sh forwards it to both qualification phases. The planner release-paths.py returns required bindings without writing any file. The installed adapter calls verify_operational on the hash-bound environment, and the format4 boot guard calls the same verifier. Bootstrap now includes that planner and the backlog producer. Nonlegacy boot refuses missing queue/state bindings. Every boot refuses pause, resume-required or unresolved state before any container action, including when the new guard is missing. These are local checks, not host evidence.

CI credentials/known-hosts/forced-command and environment selection must target the E5 deployment root. The forced command must accept only intended status/drain operations using those exact paths. Never weaken its allow-list or set format1 to bypass pause. After the audited release, qualify and observe the first real ordered update and receipt before declaring CI restored.

Manifest references are recorded in new resumptions only under manifest_claims with verified_authority=false. They are not approval or authenticated evidence.

## Restored held adoption, implemented but not host-qualified

The resolved E5 mismatch is a distinct operation, not incident recovery or UI opening. It must retain the complete prior state fingerprint and byte-hashed prior journal, preserve every history entry, verify the exact first-parent chain from the old fence to the observed new source, and append each source only once. Intermediate sources need an explicit not-delivered/restored-over outcome, never a fictitious deployment. The last appended entry must bind the actual image digest and a fresh direct held-runtime observation. Preserve all previous recoveries, append an audit with the old fence, complete chain, observed target and fresh qualification/preservation evidence produced by directly running the hash-bound installed qualification.py after phase on that digest, then advance the fence with resume_required=true. No pending or failed incident is manufactured. The CLI holds both locks and the reconciler independently proves both descriptors refer to the actual path/inode and own exclusive flock. The qualifier child inherits those locks so parent loss cannot admit another mutator. the operation retains exact pause bytes and calls the installed independent closed-runtime/preservation/gates verifier twice. No application startup, stop, gate opening or HOLD change exists in this command. The qualifier does perform an authenticated smoke on the held runtime, including session/audit activity, and then captures current stores. Old receipt JSON cannot replace this direct execution. It binds current container identity, before/policy/controller hashes, fresh after/smoke output hashes, time and store fingerprint. References inside its manifest are unverified claims, never authority.

It must not label a closed restored runtime ui-open-automation-held. E5 currently has no serving front; a new explicit restored-automation-held mode would be honest. The new operation writes format5 so old readers refuse even if they ignore an unfamiliar history mode. Generic queue readers reject format5, the boot guard rejects it, and held-update rejects it; release alone opts into reading the fenced restored state. Intermediate sources remain in the audit with explicit not-delivered outcomes, not in delivered history. Tests use real Git for first-parent-chain rejection, plus doubles for host evidence. The release adapter can now bind both existing gates and prove TLS503 rather than assuming initially open200; the entire preflight still refuses and therefore this branch is unreachable on a real host. The adapter still rejects E5's network pending the shared normal profile. Adding a journal-only shortcut without these observations would turn stale state into false proof.
